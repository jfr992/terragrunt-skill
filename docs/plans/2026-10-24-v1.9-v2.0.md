# terragrunt-skill v1.9 (Terragrunt 1.2) + v2.0 (agent-agnostic) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use `- [ ]`. Tasks tagged **[P]** touch disjoint files and may run in parallel on cheap subagents; **[S]** tasks are sequential (shared files / depend on earlier tasks).

**Goal:** Bring the skill to Terragrunt 1.2 accuracy (v1.9.0), then make it installable by any Agent Skills–compatible agent (v2.0.0).

**Architecture:** `skills/terragrunt-skill/` stays the single source of truth (SKILL.md + `references/` + `assets/`). Content tasks edit one reference each. "Tests" are shell assertions (grep / char counts / spec validator) run before and after each edit — red then green.

**Tech Stack:** Markdown, HCL, YAML frontmatter, bash, `skills-ref` validator, GitHub Actions (`.github/workflows/validate.yml`).

## Global Constraints

- Target Terragrunt **>= 1.2.0** (v1.2.0 released 2026-10-21; v1.2.1 2026-10-23). OpenTofu >= 1.10 for `use_lockfile`.
- SKILL.md frontmatter `description` (value) **<= 1024 chars** (agentskills.io spec); target <= 800. `name` == dir name `terragrunt-skill`.
- SKILL.md body < 500 lines / < 5000 tokens; references one level deep.
- CLI examples use `terragrunt run --all [flags] -- <cmd>` form.
- Every new claim cites an official link (docs.terragrunt.com or a gruntwork-io/terragrunt release). Items marked **UNVERIFIED** must keep that label in the prose (e.g. "reported in testing").
- No Claude-specific tool names in `skills/`. Do not delete `.claude-plugin/`.
- Do not push; release workflow bumps versions — do not hand-edit `CHANGELOG.md`.

```markdown
## Dependency Outputs from State (default since 1.2)

Terragrunt reads dependency outputs directly from remote state instead of running `tofu output` (no dependency init).
- Direct reads: **S3, GCS, Azure Storage (azurerm)**. Other backends fall back to `tofu/terraform output`.
- OpenTofu client-side state encryption: direct read can't decrypt → automatic fallback (speedup lost, result correct).
- Failed direct read → retried natively; `mock_outputs` only used when allowed for the command.
- Opt out: `terragrunt run --all --no-dependency-fetch-output-from-state -- plan` (env `TG_NO_DEPENDENCY_FETCH_OUTPUT_FROM_STATE`).
- Skip outputs entirely for init/validate: `--no-dependency-outputs`.
- Field report (anecdotal, one repo): warm `run --all plan` ~36s → ~23s.

Ref: https://docs.terragrunt.com/reference/experiments/completed/#dependency-fetch-output-from-state
```
